# BAMT Next

BAMT Next 是面向《碧蓝档案》国际服 / 日服PC端总力战 / 大决战的 Windows 本地宏控制台与排轴工具。它把键盘热键映射成鼠标、手牌拖动、连点、脚本序列和排轴文本管理，重点解决两件事：

- 在不同分辨率下保存、导入、换算和分享宏配置。
- 在同一个工具里完成技能宏、点位管理、AHK 兼容、排轴编辑和文本导出。

> 工具只做本机输入辅助。不同服务器、不同窗口模式和不同游戏客户端对 Windows 输入的接受程度不同，首次使用务必先在安全环境里校准并测试。

## 快速开始

1. 启动 BAMT Next。
2. 在首次弹窗中确认游戏分辨率。分辨率会影响所有坐标和手牌位置计算。
3. 进入“宏控制台”，检查默认 Q/W/E 三个技能拖动宏。
4. 首次使用必须用“捕获”重新校准手牌坐标和常用点位。
5. 输入后端默认使用“系统光标模式”。它兼容性最高，但会移动真实鼠标。
6. 点击“保存”，再点击“开始”进入监听。
7. 固定紧急停止键是 `X`。无论配置如何，遇到异常时优先按 `X` 停止监听。

## 发布版数据目录

单 exe 发布版会把所有用户数据统一写入 AppData，而不是写在 exe 同级目录。

```text
%APPDATA%/BAMT Next/data/
```

常用文件位置：

| 路径 | 内容 |
| --- | --- |
| `%APPDATA%/BAMT Next/data/config/blue_archive_config.json` | 当前宏配置。 |
| `%APPDATA%/BAMT Next/data/presets/preset-library.json` | 全局宏预设库。 |
| `%APPDATA%/BAMT Next/data/imports/` | 建议放外部导入文件。 |
| `%APPDATA%/BAMT Next/data/exports/` | 建议放导出的宏文件。 |
| `%APPDATA%/BAMT Next/data/timelines/` | 排轴编辑器自动保存的 JSON 轴文件。 |
| `%APPDATA%/BAMT Next/data/ahk/bamt-inline.ahk` | AHK 面板生成的临时脚本。 |

源码开发模式仍然使用项目内的 `data/` 目录，方便调试。

| 模块 | 用途 |
| --- | --- |
| 宏控制台 | 编辑、测试、保存和运行点位 / 拖动 / 点击 / 连点 / 脚本宏。 |

## 宏类型

| 类型 | 热键行为 | 适用场景 |
| --- | --- | --- |
| 点位 | 按住热键后在目标坐标按下，松开热键后释放并回到原鼠标位置。 | 长按某个固定点位。 |
| 拖动 | 按住热键循环执行手牌拖动。 | Q/W/E 或自定义手牌拖动。 |
| 点击 | 普通模式为单次点击；选牌键模式为循环交替点击。 | 点击 UI、模拟 1/2/3 选牌后再点鼠标当前位置。 |
| 连点 | 按住热键期间按设定间隔连续点击目标坐标。 | 高频点击固定点位。 |
| 脚本 | 执行固定 DSL 语法写出的鼠标动作序列。 | 更复杂的自定义动作。 |

## 拖动宏逻辑

当前拖动宏保留为稳定的光标宏逻辑：

1. 触发热键时记录当前鼠标位置，作为本轮释放点。
2. 鼠标移动到技能牌位坐标。
3. 按下左键。
4. 竖直向上移动设定距离。
5. 移动到触发热键时的鼠标原始位置。
6. 在原始位置释放左键。
7. 如热键仍按住，则等待一轮循环间隔后继续下一轮。

本轮拖动一旦开始就会完整走完并在原鼠标位释放；松开热键只会阻止下一轮，不会打断本轮释放。

可调参数：

- `距离`：向上拖动的像素距离，默认 `300`。
- `时长`：一次拖动动作的移动时长，默认 `0.02`。
- `循环间隔`：每轮拖动之间的等待时间，默认 `0.05`。拖动宏不建议低于 `0.05`，否则系统光标模式会明显抢鼠标。
- `手牌点击偏移 / 虚拟步长`：用于微调手牌起点和移动过程。修改后点“应用并重算”。

注意：拖动宏属于游戏底部 UI 手牌映射，不和战场地图点位使用同一套换算算法。

## 点击宏逻辑

点击宏有两种用法：

1. 普通点击：按下热键后点击配置坐标一次。
2. 选牌键点击：配置 `选牌键` 为 `1`、`2` 或 `3` 后，按住热键会循环执行：

```text
按键 1/2/3 -> 等待“单轮内间隔” -> 点击当前鼠标位置 -> 等待“循环间隔” -> 下一轮
```

可调参数：

- `单轮内间隔`：一次循环内，选牌键和鼠标点击之间的间隔，默认 `0.005`。
- `循环间隔`：两轮循环之间的间隔，默认 `0.005`。

## 输入后端

| 后端 | 说明 | 推荐程度 |
| --- | --- | --- |
| 系统光标模式 | 通过真实系统光标执行输入。适配度最高，通常能进原生游戏；缺点是会移动并占用真实鼠标。 | 默认推荐 |
| Win 窗口消息模式 | 不移动真实光标，体验最好；但游戏聚焦后会拒收窗口消息。 | 视情况而定 |
| Win 触控注入模式 | 模拟 Windows 触控输入，不抢鼠标；目前仍在测试，兼容性不稳定。 | 实验功能 |

如果国际服可用、日服聚焦后热键无效，优先尝试：

- 使用“系统光标模式”。
- 以管理员身份启动 BAMT Next。
- 确认状态记录里能看到热键触发日志。
- 避免在游戏启用了会屏蔽全局钩子的覆盖层或安全设置。

## 键盘接管与紧急停止

键盘接管模式默认关闭。开启后，监听期间会尽量屏蔽普通键盘输入，只保留宏热键和固定紧急停止键。

- 固定紧急停止键：`X`。
- `X` 不允许被改成其他键。
- 修改宏配置、切换分辨率、导入宏时，建议先停止监听。

## 坐标和分辨率映射

BAMT 现在把坐标分成两类处理：

1. 战场地图点位：点位、点击、连点使用“中轴线缩放”规则。它适合游戏画面里的地图坐标、技能释放点、敌人位置和场地位置。
2. 游戏 UI 手牌：拖动宏使用底部 UI 锚定算法。它适合 Q/W/E 这种底部技能卡位置。

Q/W/E 三个基础手牌拖动宏还有独立算法，不和普通点位混算。导入别人配置后，应先点“应用并重算”或“重算技能位”，然后手动校准一次。

## 宏预设导入导出

宏预设用于分享或备份一整套点位、拖动、点击、连点和脚本宏。

| 操作 | 说明 |
| --- | --- |
| 保存预设 | 把当前宏配置保存到全局预设库。 |
| 加载预设 | 从预设库恢复一套配置，坐标会按当前分辨率换算。 |
| 导出当前 | 导出当前宏配置。 |
| 导出全部 | 导出当前宏配置和预设库里的全部配置。 |
| 导入全局宏 | 导入别人分享的宏配置，加入预设库。 |
| 合并全局宏 | 把外部文件里的宏合并进当前配置。 |
| 导入 AHK | 尝试解析 AHK 文件中的点击、拖动、连点等坐标逻辑 |

推荐把需要分享的文件放在 `data/exports/`，把收到的外部文件先放在 `data/imports/`。

## 排轴编辑器

排轴编辑器按 P 完全独立管理。P1、P2、P3 可以有完全不同的角色、练度、牌序和动作记录。

### 新建和保存

- 新建轴前先填写文件名。
- 点击“新建轴”会在 `data/timelines/` 创建新的 JSON 文件。
- 初始角色使用 `角色1` 到 `角色6`，不会写死具体学生名。
- 编辑时会自动保存，不需要每次手动导出。
- 导出 TXT / MD / JSON 时，默认文件名使用排轴编辑器里设置的文件名。

### 队伍和练度

每个 P 都有自己的：

- 队伍名称。
- 角色 1 到角色 6。
- 参考练度文本。
- 点位 / 视频参考。

参考练度模板会根据当前 P 的角色生成，格式类似：

```text
角色名    3x   5MMM   101010   ❤20
```

玩家可以直接编辑模板文本。

### 牌序

先按顺序选择 5 张牌：

- 第 1 到第 3 张：初始牌。
- 第 4 到第 5 张：固定顺序牌。
- 第 6 张：未选择的剩余角色自动补上。

如果出场人数不足 6 人，就按实际人数组成牌池，但出牌区仍最多显示 3 张。

### 出牌逻辑

出牌区只有前 3 张牌可释放。释放后根据模式更新牌池：

- 普通沉底：该牌移动到牌池末尾。
- 锁牌留位：该牌仍留在原位置，牌序不变。
- 复制留位：复制其他学生，显示为 `被复制角色（复制）`。复制牌留在原位；再次释放复制牌后，复制状态结束并恢复原角色名，然后沉底。

复制牌不能复制自己，只能复制其他在场学生。允许出牌区同时出现原角色自己的牌和复制出来的牌。

### 轴事件

下一张牌可以按三类释放条件记录：

- 时间。
- 费用。
- 衔接上一张牌。

另有三个结构事件：

- 转场：在文本里单独画线标记转场。
- 撤退并进入下一 P：标记当前 P 撤退，并新建下一 P。
- 送人：在时间轴当前位置标记角色阵亡，格式为 `---送人：角色名`。

送人是沿时间发生的事件，只影响它之后的牌池。删除送人记录后，后续牌池会重新按时间线回放计算，角色会恢复。

### 文本预览

文本预览会把所有 P 的信息集中放在开头：

```text
总力战轴
P1：...
P2：...
牌序： ...
参考练度：
P1:
...
视频参考：
...
P1
...
P2
...
```

可以点击“独立预览”打开新的置顶窗口，边看轴边操作游戏。

## 脚本宏 DSL

脚本宏不是 Python，也不是完整 AHK。它是 BAMT 后端解析的固定安全语法。

规则：

- 一行一条命令。
- 空行忽略。
- `#`、`//`、`;` 开头是注释。
- 坐标是当前分辨率下的屏幕坐标。
- 时间单位是毫秒。
- `mouse` 表示触发热键瞬间的鼠标位置。

### 命令

| 命令 | 示例 | 说明 |
| --- | --- | --- |
| `click` | `click 1500 900` | 点击坐标。 |
| `press` | `press 1200 800` | 移动到坐标并按下左键。 |
| `release` | `release mouse` | 在指定位置释放左键。 |
| `move` | `move 2688 1500 80` | 用约 80ms 移动到坐标。 |
| `move mouse` | `move mouse 45` | 用约 45ms 回到触发热键时的鼠标位置。 |
| `drag` | `drag 1000 1400 1000 1100 80` | 从起点拖到终点。 |
| `curve` | `curve 1000 1400 1150 1280 1320 1220 180` | 多点分段移动。 |
| `sleep` | `sleep 50` | 等待 50ms。 |
| `loop until_release` | 见下方示例 | 按住热键时循环，松开后停止。 |
| `release_actions` | 见下方示例 | 脚本结束后的兜底动作。 |

### 示例：拖到鼠标当前位置释放

```text
press 2688 1853
move 2688 1553 20
move mouse 10
release mouse
```

### 示例：按住热键循环

```text
loop until_release
  press 2688 1853
  move 2688 1553 20
  move mouse 10
  release mouse
  sleep 5
end
release_actions
  release mouse
```

分享脚本宏时建议写清楚基准分辨率。

## AHK 解释器

BAMT Next 内置 AutoHotkey v2 桥接能力：

- AHK 面板可以运行临时脚本。
- 临时脚本写入 `data/ahk/bamt-inline.ahk`。
- 解释器优先使用 `tools/AutoHotkey/AutoHotkey64.exe`。
- 如果解释器缺失，可设置环境变量 `BAMT_AHK` 指向 `AutoHotkey64.exe`。

AHK 文件导入用于把社区脚本转换成 BAMT 宏预设；它不会无条件把外部脚本逻辑塞进当前工程。

## 常见问题

### 后端进程已退出 / Python was not found

说明 Electron 找不到可用 Python。处理顺序：

1. 安装 Python 3。
2. 关闭 Windows 的 Microsoft Store `python.exe` / `python3.exe` 执行别名。
3. 设置 `BAMT_PYTHON` 指向真实 `python.exe`。

### 日服点击窗口后热键无效

通常是游戏聚焦后拒收窗口消息或权限层级不一致。

建议：

1. 使用“系统光标模式”。
2. 以管理员身份启动 BAMT Next。
3. 在状态记录里确认热键是否被监听到。

### 窗口模式不移动光标但没有效果

这是窗口消息模式的兼容性限制。它不保证能进所有 DirectX / 原生游戏窗口。能用时体验最好，不能用时切回系统光标模式。

### 坐标导入后偏移

先确认导入文件的基准分辨率和当前游戏分辨率。战场点位和手牌 UI 使用不同映射算法，Q/W/E 导入后建议手动校准。
