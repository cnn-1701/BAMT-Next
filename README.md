# BAMT Next

BAMT Next 是面向《碧蓝档案》PC 端总力战 / 大决战的 Windows 本地宏控制台与排轴工具。它把热键、鼠标动作、分辨率换算、宏预设、AHK 测试脚本和排轴文本管理放在同一个桌面应用里。

> 这是本机输入辅助工具。不同服务器、不同窗口模式、不同权限层级对 Windows 输入的接收情况会不一样。第一次使用务必先在安全环境里校准和测试。

## 当前稳定点

本版本把视觉宏暂时剥离出主流程，保留已经能工作的基础宏、最速出牌测试、AHK 解释器、排轴编辑器和预设管理。  
如果后续实验功能改坏了，可以回滚到带有 `stable` 字样的 Git 提交或标签。

## 快速开始

1. 启动 BAMT Next。
2. 先确认游戏分辨率。分辨率会影响所有坐标和手牌位置计算。
3. 进入「宏控制台」，检查默认 Q/W/E 宏。
4. 第一次使用必须用「捕获」重新校准手牌坐标和常用点位。
5. 输入后端默认建议使用「系统光标模式」。它兼容性最高，但会移动真实鼠标。
6. 保存配置后点击「开始」进入监听。
7. 固定紧急停止键是 `X`。遇到异常时优先按 `X` 停止监听。

## 发布版数据目录

单 exe 发布版不会把用户数据写在 exe 同级目录。配置、宏预设、排轴、导入导出文件统一放在：

```text
%APPDATA%/BAMT Next/data/
```

常用位置：

| 路径 | 内容 |
| --- | --- |
| `%APPDATA%/BAMT Next/data/config/blue_archive_config.json` | 当前宏配置 |
| `%APPDATA%/BAMT Next/data/presets/preset-library.json` | 全局宏预设库 |
| `%APPDATA%/BAMT Next/data/imports/` | 建议放外部导入文件 |
| `%APPDATA%/BAMT Next/data/exports/` | 建议放导出的宏文件 |
| `%APPDATA%/BAMT Next/data/timelines/` | 排轴编辑器自动保存的 JSON 轴文件 |
| `%APPDATA%/BAMT Next/data/ahk/bamt-inline.ahk` | AHK 面板生成的临时脚本 |

源码开发模式使用仓库内的 `data/` 目录，方便调试。

## 功能模块

| 模块 | 用途 |
| --- | --- |
| 宏控制台 | 编辑、测试、保存和运行点位、拖动、点击、连点、脚本宏 |
| 点位转换器 | 在不同分辨率之间换算坐标 |
| 排轴编辑器 | 按 P 独立管理队伍、练度、牌序、动作、备注和文本导出 |

## 宏类型

| 类型 | 热键行为 | 适用场景 |
| --- | --- | --- |
| 点位 | 按下热键后移动到目标坐标，松开热键后释放并回到原鼠标位置 | 长按某个固定点 |
| 拖动 | 按住热键循环执行手牌拖动 | Q/W/E 或自定义手牌拖动 |
| 连点 | 按住热键期间按设定间隔连续点击目标坐标 | 高频点击固定点 |
| 点击 | 普通点击，或配置选牌键后执行最速出牌点击 | UI 点击、1/2/3 选牌后点当前鼠标 |
| 最速出牌 | 按住热键循环执行「选牌键 + 当前鼠标左键」 | 不需要拖牌、只需要快速出牌的场景 |
| 脚本 | 执行 BAMT DSL 或保存脚本内容 | 更复杂的自定义动作 |

## 拖动宏逻辑

拖动宏属于底部手牌 UI 宏，不和战场点位使用同一套映射算法。

一轮循环的逻辑：

1. 触发热键时记录当前鼠标位置，作为本轮释放点。
2. 光标移动到计算出的手牌位置。
3. 按下左键。
4. 竖直向上移动设定距离。
5. 移动到触发热键时的鼠标原始位置。
6. 在原始位置释放左键。
7. 如果热键仍按住，等待循环间隔后开始下一轮。

注意：系统光标模式本质上一定会移动真实鼠标。循环间隔太短时，手动移动鼠标会明显感觉被抢。需要更少抢鼠标时，优先提高循环间隔，而不是继续压低动作时长。

## 点击宏与最速出牌

点击宏有两种用法：

1. 普通点击：点击配置坐标一次。
2. 选牌键点击：配置 `1`、`2` 或 `3` 后，按住热键循环执行：

```text
按 1/2/3 -> 等待单轮内间隔 -> 点击当前鼠标位置 -> 等待循环间隔 -> 下一轮
```

可调参数：

- `单轮内间隔`：选牌键和鼠标点击之间的间隔。
- `循环间隔`：两轮循环之间的间隔。
- `点击按住时长`：鼠标左键按下到释放之间的时长。

## AHK 与 Python 输入路线的实测结论

游戏内测试发现，同样执行「按 1/2/3 选牌，再点击当前鼠标位置」时，AutoHotkey v2 的 `SendInput` / `Click` 路线比 Python 后端手动拼接 `ctypes + SendInput + 鼠标事件` 更不容易卡牌。

目前判断：

- AHK 的 `SetMouseDelay(-1)`、`SetKeyDelay(-1, -1)` 和 `SendMode("Input")` 形成的输入事件更短、更连续。
- Python 后端需要同时处理配置、坐标映射、鼠标保护、回原位和多输入后端，更容易被游戏帧采样到中间态。
- 对「最速出牌」这种不需要移动到固定点的操作，优先使用「选牌键 + 当前鼠标点击」短链路。
- 如果 Python 最速出牌卡牌，先在 AHK 解释器运行默认测试脚本，确认游戏是否接收 AHK 输入。

## AHK 解释器测试脚本

内置 AHK 面板的默认脚本用于测试最速出牌输入链路：

```text
按住 Q：循环发送 1，然后点击当前鼠标位置
按住 W：循环发送 2，然后点击当前鼠标位置
按住 E：循环发送 3，然后点击当前鼠标位置
F11：暂停 / 继续脚本
F12：退出脚本
```

默认脚本使用 AutoHotkey v2：

```ahk
SetMouseDelay(-1)
SetKeyDelay(-1, -1)
SendMode("Input")
```

如果 AHK 测试能稳定出牌，而 Python 最速出牌卡牌，说明游戏更接受 AHK 的输入队列节奏。后续可以把 AHK 路线作为专门的高频出牌后端继续发展。

## 脚本宏与 AHK 导入

脚本宏建议通过「新增脚本宏」创建，然后自行命名、填写热键和脚本内容。已有 `.ahk` 文件可以用「导入 AHK 为脚本宏」保存进当前宏配置。

需要区分：

- **AHK 解释器**：直接运行 AutoHotkey v2 脚本，适合临时测试输入链路。
- **AHK 导入宏**：把 `.ahk` 文件作为宏素材导入。可以解析成 BAMT 坐标宏，也可以作为脚本宏保存，并随全局预设一起导入、导出、合并。

全局宏预设导入 / 导出会保留脚本宏的 `script` 内容。合并导入时，外部文件里的脚本宏会追加到当前配置，不会覆盖已有宏。

## 输入后端

| 后端 | 说明 | 推荐程度 |
| --- | --- | --- |
| 系统光标模式 | 通过真实系统光标执行输入。兼容性最高，通常能进原生游戏；缺点是会移动真实鼠标 | 默认推荐 |
| Win 窗口消息模式 | 不移动真实光标，体验最好；但部分原生游戏聚焦后会拒收窗口消息 | 视情况使用 |
| Win 触控注入模式 | 模拟 Windows 触控输入，不抢鼠标；目前仍在测试，兼容性不稳定 | 实验功能 |

如果国际服可用、日服聚焦后热键无效，优先尝试：

1. 使用「系统光标模式」。
2. 以管理员身份启动 BAMT Next。
3. 在状态记录里确认热键是否被监听到。

## 键盘接管与紧急停止

键盘接管模式默认关闭。开启后，监听期间会尽量屏蔽普通键盘输入，只保留宏热键和固定紧急停止键。

- 固定紧急停止键：`X`
- `X` 不允许改成其他键。
- 修改宏配置、切换分辨率、导入宏前，建议先停止监听。

## 坐标和分辨率映射

BAMT 把坐标分成两类：

1. **战场地图点位**：点位、点击、连点使用「中轴线缩放」规则，适合技能释放点、敌人位置、场地位置。
2. **游戏 UI 手牌**：拖动宏使用底部 UI 锚定算法，适合 Q/W/E 这类底部技能卡位置。

Q/W/E 三个基础手牌拖动宏有独立算法，不和普通点位混算。导入别人配置后，应先点「应用并重算」或「重算技能位」，再手动校准一次。

## 宏预设导入导出

宏预设用于分享或备份一整套点位、拖动、点击、连点和脚本宏。

| 操作 | 说明 |
| --- | --- |
| 保存预设 | 把当前宏配置保存到全局预设库 |
| 加载预设 | 从预设库恢复一套配置，坐标按当前分辨率换算 |
| 导出当前 | 导出当前宏配置 |
| 导出全部 | 导出当前宏配置和预设库里的全部配置 |
| 导入全局宏 | 导入别人分享的宏配置，加入预设库 |
| 合并全局宏 | 把外部文件里的宏合并进当前配置 |
| 导入 AHK | 尝试解析 AHK 文件中的点击、拖动、连点等坐标逻辑 |

建议把要分享的文件放在 `data/exports/`，把收到的外部文件先放在 `data/imports/`。

## 排轴编辑器

排轴编辑器按 P 完全独立管理。P1、P2、P3 可以有完全不同的角色、练度、牌序和动作记录。

### 新建和保存

- 新建轴前先填写文件名。
- 点击「新建轴」会在 `data/timelines/` 创建新的 JSON 文件。
- 初始角色使用 `角色1` 到 `角色6`，不会写死具体学生名。
- 编辑时会自动保存。
- 导出 TXT / MD / JSON 时，默认文件名使用轴名称。

### 队伍和练度

每个 P 都有自己的：

- 队伍名称
- 角色 1 到角色 6
- 参考练度文本
- 点位 / 视频参考

参考练度模板会根据当前 P 的角色生成，格式类似：

```text
角色名    3x   5MMM   101010   ❤20
```

### 牌序

按顺序选择 5 张牌：

- 第 1 到第 3 张：初始牌。
- 第 4 到第 5 张：固定顺序牌。
- 第 6 张：未选择的剩余角色自动补成。

出场人数不足 6 人时按实际人数组成牌池，但出牌区仍最多显示 3 张。

### 出牌逻辑

出牌区只有前 3 张牌可释放。释放后根据模式更新牌池：

- 普通沉底：该牌移动到牌池末尾。
- 锁牌留位：该牌仍留在原位置，牌序不变。
- 复制留位：复制其他学生，显示为「被复制角色（复制）」。复制牌留在原位；再次释放复制牌后，复制状态结束并恢复原角色名，然后沉底。

复制牌不能复制自己，只能复制其他在场学生。

### 轴事件

下一张牌可以按三类释放条件记录：

- 时间
- 费用
- 衔接上一张牌

结构事件：

- 转场：在文本里单独画线标记转场。
- 撤退并进入下一 P：标记当前 P 撤退，并新建下一 P。
- 送人：沿时间轴标记角色阵亡，格式为 `---送人：角色名`。

送人只影响它之后的牌池。删除送人记录后，后续牌池会按时间线重新计算，角色会恢复。

## 脚本宏 DSL

脚本宏不是 Python，也不是完整 AHK。它是 BAMT 后端解析的固定语法。

规则：

- 一行一条命令。
- 空行忽略。
- `#`、`//`、`;` 开头是注释。
- 坐标是当前分辨率下的屏幕坐标。
- 时间单位是毫秒。
- `mouse` 表示触发热键瞬间的鼠标位置。

示例：

```text
loop until_release
  press 2688 1853
  move 2688 1553 20
  move mouse 10
  release mouse
  sleep 50
end
release_actions
  release mouse
```

## 从源码运行

```powershell
npm install
npm run dev
```

如果 Python 后端启动失败，可以安装 Python 3，或设置：

```powershell
$env:BAMT_PYTHON = "C:\Path\To\python.exe"
npm run dev
```

```powershell
npm run dist
```

```text
release/
```

- `backend/`
- `tools/AutoHotkey/AutoHotkey64.exe`
